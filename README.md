# B站/小红书/YouTube 学习笔记助手

## English Introduction

**Bilibili / Xiaohongshu / YouTube Study Note Assistant** — a lightweight, free browser extension that turns videos into structured study notes:

1. Paste a video link (Bilibili multi-part supported via `&p=N`; Xiaohongshu video notes and YouTube videos are also supported).

2. Automatically fetch the subtitles (Bilibili's AI subtitles need a Bilibili login to read; Xiaohongshu reads the `.srt` track stored in the note page; YouTube uses a page hook / in-page fetch / CDP network fallback to get past the PoToken check).

3. One click sends the subtitles to **Doubao**, a free AI chatbot, with a tailored prompt.

4. Doubao outputs a clean Markdown note in six sections: **Key Points**, **Glossary**, **Pitfalls & Questions**, **Mind Map** (an expandable knowledge tree using Obsidian callouts), **Key Timestamps** (`[mm:ss]` plus what happens at that point), and the **verbatim transcript**. Math is converted to standard LaTeX (`$U_{CE}$`, `$$\frac{a}{b}$$`).

5. Automatically saves the note into **Obsidian** via the free Local REST API plugin — works continuously for multiple videos, and note titles follow each video's own title.

6. Two optional toggles: turn every `[mm:ss]` in Key Timestamps into a click-to-seek link; and auto-capture 3–5 key frames from the already-open video page, with the PNGs written into your vault and inserted **right under the matching timestamp line** in the Key Timestamps section.

Everything is free and local-first: no API keys, no models to download, no data collection. Notes go only to your own Doubao conversation and your local Obsidian vault.

一个**网页式**的免费工具（基于浏览器扩展实现）：打开网页界面 → 粘贴 **B 站 / 小红书 / YouTube** 视频链接 → 自动抓取字幕 → 一键发送给豆包 → 豆包免费输出**六板块结构化笔记**（核心要点 / 术语表 / 易错点与疑问 / 思维导图 / 关键节点 / 原始字幕），整理结果**自动存入 Obsidian**（可选），**支持连续处理多个视频**。

> **YouTube 说明（v3.7.94 更新）**：YouTube 从 2024 年起给字幕接口（`api/timedtext`）加了 **PoToken 校验**——直接用接口请求会返回 200 但内容为空，`get_transcript`（显示文稿）接口报 400。所以插件走三条通路，按顺序自动尝试：①**页面钩子缓存**（`hook-youtube.js` 在页面里钩住播放器发出的字幕请求，你只要在播放器里点开「字幕 / CC」并播放几秒）；②**页面内直取**（读 `performance` 里已请求过的 timedtext 地址，把带 pot 的 URL 再取一次）；③**调试器网络抓取**（v3.7.94 新增兜底：临时用 CDP 监听网络，直接取播放器自己的字幕响应体，并自动点一次 CC 按钮触发请求；结束立即撤销，页面顶部黄条自动消失，无需你手动操作）。三条都不通时，错误提示会带一行「诊断：钩子是否注入、缓存几条、资源记录几条、轨道数、有没有 CC 按钮」，照着就能定位。YouTube 字幕同样中文优先（有 `zh` 轨取中文，否则取第一条）。

> **小红书说明（v3.7.89 新增 / v3.7.90 修轨道选择）**：小红书视频的字幕以 `.srt` 文件存放在笔记页数据里，插件直接从页面抓取并转成 `[mm:ss]` 字幕行，流程与 B 站完全一致（单条界面 + 队列自动填下一个）。字幕数据里可能同时存在三条轨道：`en-US`（英文）、`source`（原始/作者字幕，language 为 zh-CN）、`zh-CN`（AI 中文）。插件按 **zh-CN → source → 任意中文 → 兜底** 的顺序选，所以**不是 AI 字幕的（作者字幕）同样能读**，也不会误抓成英文。没有字幕轨道的笔记会明确提示，不会抓错内容。

- 不需要下载任何模型、不需要申请任何 API Key、不花一分钱

- 字幕只发给你自己的豆包对话框，不经过任何第三方服务器

- 公式在 Obsidian 中由内置 MathJax 原生渲染（`$$...$$`），物理量符号自动转标准下标（`UD`→`$U_D$`、`UZ`→`$U_Z$`、`R1`→`$R_1$`；豆包已输出的 LaTeX 下标如 `U_{CE}` 原样保留，不会二次破坏）

- 思维导图是可点击展开的知识树（Obsidian 原生 callout `> [!note]-`）：每个核心板块一个折叠块，点击标题展开该板块的详细讲解（v3.7.44+）

- **六板块结构化笔记（v3.7.96）**：核心要点、术语表、易错点与疑问、思维导图、关键节点；原始字幕由插件在保存时自动追加到文末折叠块，不经过豆包输出，随时可对照。保真优先：数字、时间、专名、公式、条件限定原样保留，不确定的内容只写成【疑问】，不编答案；保存前做时间戳自检，笔记里出现而字幕中不存在的时间戳会在保存提示里标出。

- 自动过滤杂鱼内容（字幕回显、历史对话、重复回答），同一回答只保存一次
- **关键画面截图（v3.8.0 开关 / v3.8.4 插到正文）**：勾选后，抓完字幕会自动截 3~5 张关键画面。时间点优先挑字幕里出现画面词的行（"这张图 / 如图 / 波形 / 曲线 / 电路 / 接线 / 参数表 / 画 / 这个位置"），一个都没有时按视频长度均匀取样。图片存到 `mynote/attachments/`，保存时**插到「关键节点」板块里距截图 ±90 秒最近的那条下面**（该条是列表项就缩进 2 空格，非列表项顶格）；离最近的节点也超过 90 秒时放到该板块最后一条下面；整篇找不到「关键节点」板块才退回文末「六、关键画面」大图块（标题写成「关键时间点 / 时间节点 / 关键画面节点」同样能认出来）。每张图落在哪里都会写进保存提示，不静默处理。
  - **只在你已经打开的那个 B 站视频页里截**：临时跳到该时间点、暂停，截完把播放位置和播放状态还原、把临时隐藏的控件恢复。**不会为你新开标签页**（这是硬约束）。没有打开该视频页、播放区域太小、调试器附加失败、写库失败，都会在状态栏写明原因，不会静默丢图。
  - 截图走 CDP `Page.captureScreenshot`（不是 canvas——B 站视频跨域会污染 canvas，`toDataURL` 拿不到数据）；截的是播放器矩形区域，不含边栏与弹幕。
  - **v3.8.1 自愈**：在 `edge://extensions` 点「重新加载」后，已经打开的页面里旧内容脚本的通道会失效（页面正常但不再响应消息，状态栏表现是每个时间点都"页面通信失败"）。现在失败时会自动往该页面补注入一次脚本并重试，成功时状态栏会写"已自动补注入页面脚本，无需刷新"；补注入也失败才提示刷新页面（F5）。
  - **v3.8.2 精度修正**（针对"截出来有空白的、有截不全的"）：
    - 只截**真实画面**：按 `videoWidth/videoHeight` 把播放器里的黑边算掉，不再把上下/左右黑边当内容截进来。
    - 不再靠固定等待：seek 后用 `requestVideoFrameCallback` 等浏览器真正呈现一帧，并校验 `readyState>=2`；该时间点没缓冲就跳过并写明"未缓冲"，绝不把黑帧写进笔记。
    - 落盘前做空白检测（缩略采样算亮度均值与方差）：近纯黑/近纯白且几乎无变化的图会被**丢弃并重试一次**，仍空白就报"截到黑帧/白帧（实际尺寸），已丢弃"，不会出现在笔记里。
    - 播放器比窗口还高（网页全屏/剧场模式）时，临时把虚拟视口撑高再截，截完立刻撤销，保证整块画面都在图里。
    - 状态栏会带"实际尺寸 vs 期望尺寸"的偏差提示，便于确认是否是窗口太小导致裁边。
    - **v3.8.3**：截图尺寸按"裁剪 CSS 尺寸 × 设备像素比"核对——系统缩放 150%/200% 时图会比 CSS 尺寸大 1.5/2 倍（例如 668×376 裁出来是 1336×752），这是更清晰，不是裁边，不再误报；某个时间点没解码出画面时多给 2.5 秒缓冲时间再判失败。
    - **v3.8.5**：修连续发送时"同一条字幕被发两遍"。三处改动：①给豆包页发送流程加互斥（`storage.onChanged` 与 1 秒轮询同时进来时只放一个通过，原来两个都读到同一条待发送记录 → 发两次）；②删待发送标记改为**等它真正落盘**再继续（原来不等待，下一轮轮询可能还读得到）；③点完发送后判定"输入框是否已清空"的宽限从 1.2 秒放宽到 2.5 秒——豆包反应慢时输入框要过一会儿才清空，原来会误判成"没发出"，再补按一次回车就变成两条提问。
    - **v3.8.6**：修「豆包输出一半就开始改公式」。根因是插件只按“文本 12 秒没变化”判完成——豆包写长笔记时中途停顿（写公式、分块渲染）被当成写完，于是立刻发【公式修正请求】打断正在进行的生成。三处改动：①先看页面上还有没有“停止生成”控件，有就一律算还在写，文本停多久都不判完成；②长笔记（≥1200 字）的稳定阈值从 12 秒提到 30 秒（专家模式 24 → 42 秒）；③判定达标后再多等一轮，连续两次采样都不变才落盘。文本骤降的完成判定也加了同样的生成中检查。豆包的“停止生成”按钮只挂图标、没有可匹配类名时，还会按按钮自身的无障碍文本（“停止”/“停止生成”/“Stop”）再查一遍；若连续命中 40 轮（约 2 分钟）仍判不出来，就认定是选择器误伤，本次监控改用纯文本阈值，不会永久卡住。
    - **v3.8.4**：关键画面不再集中堆在文末。保存时在「关键节点」板块里找距该截图 ±90 秒最近的时间戳行，把 `![[...]]` 插在该行正下面；90 秒内没有对应节点就放到该板块末尾；整篇没有该板块才退回文末「六、关键画面」。每张图的落位都写进保存提示（"N 张图已插在关键节点对应时间点下面" / "N 张图 90 秒内没找到对应节点…"）。
- **时间戳跳转链接（v3.8.0，按钮开关）**：勾选后，笔记「关键节点」里的 `[mm:ss]` 变成可点链接（`...?t=秒`，分 P 保留 `p=`），点一下回到视频对应画面。只处理行首 `[mm:ss]`，文末原始字幕折叠块（每行以 `>` 开头）不动，公式里的 `$` 不受影响。
- 两个开关各自独立、默认关闭，勾选状态记在本机；关掉就完全回到纯文字笔记。
- **防串号（v3.7.98）**：连续处理多个视频时，新视频刚发送、豆包还没开始写新回答的几秒里，页面上"最后一条回答"仍是上一条视频的笔记。现在发送前会记录当前回答的指纹作为基线，文本与基线完全一致就判定"新回答尚未出现"继续等；同时校验回答里的笔记标题与本次视频标题一致（允许标点/空格差异），不一致绝不写盘。等满 5 分钟仍不匹配会明确提示"回答仍是上一条，本次未写入"，而不是把上一条悄悄存成这一条。截图数据同样按这条约束走：每次抓字幕先清空、只在 6 小时内且属于本次发送时才用。

## 一、安装（1 分钟）

1. 解压本压缩包，得到 `bilibili-note-extension` 文件夹。

2. 打开 Edge（或 Chrome），地址栏输入 `edge://extensions`（Chrome 用 `chrome://extensions`）回车。

3. 打开左下角「开发人员模式」开关。

4. 点左上角「加载解压缩的扩展」，选择 `bilibili-note-extension` 文件夹。

> 升级新版本：在 `edge://extensions` 里找到本扩展，点「重新加载」（↻）即可；确认版本号与最新一致（当前 **v3.8.6**）。

## 二、前提：登录豆包网页版（只需一次）

浏览器扩展只能操作**豆包网页版**，不能操作豆包桌面客户端。

1. 在 Edge 地址栏打开 [https://www.doubao.com/](https://www.doubao.com/)。

2. 用你的豆包账号登录（手机号扫码即可，和客户端同一个账号，免费）。

3. 登录后保持登录态即可。

4. **同时请确认 Edge 已登录 B 站账号**（在 Edge 里打开 [https://www.bilibili.com/](https://www.bilibili.com/)，点右上角头像登录）。读取 B 站的 **AI 智能字幕（自动生成字幕）必须登录**，与播放器里能否开「智能字幕」一致。未登录时接口不会返回任何字幕。

5. 小红书不需要额外配置（登录了更好，抓取时会复用页面登录态）。若你想从**已打开**的小红书笔记页抓，插件会直接在那个页面里取字幕，最稳。

## 二・五、接入 Obsidian（可选，自动保存笔记）

如果你想把整理好的笔记自动存进 Obsidian（本地笔记库），配置一次即可：

1. **安装 Obsidian**：到 [https://obsidian.md](https://obsidian.md) 下载安装，装完创建一个笔记库（Vault），选一个文件夹即可（如 `D:\MyNotes`）。

2. 打开 Obsidian → 左下角设置 → 「第三方插件」→ 关闭「安全模式」→ 点「浏览」进入社区插件市场。

3. 搜索 **Local REST API**，安装并启用（免费）。

4. 打开 Local REST API 的插件设置：**打开「Enable Insecure Server」（启用 HTTP 服务器）开关**——插件默认主端口是 27124（HTTPS，浏览器不认它的自签名证书），必须启用 HTTP 后扩展才能用 `http://127.0.0.1:27123` 连接；记下 **API Key**。

5. 打开本扩展网页入口，在「Obsidian 自动保存设置」里：**API 地址**保持 `http://127.0.0.1:27123` 默认值（除非你改过端口），**API Key** 粘贴插件里显示的 Key，**保存目录只填 vault 内的相对路径**（如 `笔记` 或 `学习笔记/`，**不要填绝对路径**），点「保存设置」。

6. 之后每次发送给豆包整理，豆包回答完会**自动存成 .md 笔记**到 Obsidian（文件名 = 视频标题 + 日期，默认存库根目录；可在设置里填子目录如 `学习笔记/`）。

### 笔记格式与公式渲染（无需额外插件）

- 公式输出为标准 LaTeX：正文物理量自动转行内公式（`$I_D$`），大公式用 `$$...$$` 块。
- **公式自检闭环（v3.7.56+）**：转换后自动检测"疑似未转公式"残留（形态检测，不认具体符号）；若发现残留，自动把笔记发回豆包再修一轮（≤2 轮，豆包懂语义、负责改对），达标后才写入 Obsidian——不再靠正则穷举符号，新出现的任何符号都能被自动发现并修正。
- **行内公式收尾规整（v3.7.97）**：转换出口再加一道规整，清掉逐符号规则遗留的三类坏形态——`$` 被插进下标花括号内部（`g_{$m}`、`V_{GS$(TH)}`）、整条等式被切成多段碎片 `$`、只包了前半段的半包公式；处理前先保护 `$$` 块、代码块和行内代码，合法公式原样不动。
- **假 `$$` 与单边 `$`（v3.7.99）**：行内公式被多塞一个 `$` 时会形成假 `$$`（如 `\frac{V_{DD}}{R_{D}$$}$`），`$$` 是块级分界，两个假 `$$` 配对后会把中间几十行正文一起当公式块渲染，这就是"改了还有部分乱码"的主因。现在只有**行首** `$$` 才算块边界，行内出现的 `$$` 一律折成 `$`；回答被截断留下的单边 `$`（行尾只剩数学字符时补收口 `$`，否则删掉）也会被清掉。另外合并豆包修正行后、写盘前会对全文再消毒一次，修正行自带的碎片 `$` 不会再漏进笔记。

- Obsidian **内置 MathJax** 原生渲染 `$$...$$`，零依赖、零网络，打开笔记即显示公式，**不需要安装任何公式插件**。

## 三、使用

> **重要：不要直接双击打开 `app.html` 文件！** 页面必须通过扩展运行（点工具栏「B」图标或 B 站/小红书/YouTube 页「笔记」按钮打开），否则会报 `Cannot read properties of undefined (reading 'sendMessage')` 错误。

### 打开网页入口

- **方式一**：点击浏览器工具栏上的蓝色「B」图标；

- **方式二**：在任意 B 站视频播放页，点击右下角浮动的「笔记」按钮（会自动带上当前视频链接）；

- **方式三**：在任意**小红书笔记页**（`xiaohongshu.com/explore/...` 或 `rednote.com/discovery/item/...`），点击右下角浮动的「笔记」按钮（自动带上当前笔记链接，并从该页面内抓字幕，最稳）；

- **方式四**：在任意 **YouTube 视频页**（`youtube.com/watch?v=...`），点击右下角浮动的「笔记」按钮（自动带上当前视频链接；YouTube 必须先在这个页面开过字幕，页面内钩子才能缓存到字幕正文）。

### 完整流程

1. 顶部先选平台（**B站 / 小红书 / YouTube** 三个切换键，粘贴的链接属于哪家会自动切过去），再把视频链接粘贴到输入框（B 站支持分 P：链接后加 `&p=3` 表示第 3 集；小红书粘完整笔记链接，含 `xsec_token` 的那串；YouTube 粘 `watch?v=...` 或 `youtu.be/...`），点「**抓取字幕**」。

2. 页面显示视频标题、字幕条数与字幕预览。

3. 点「**发送到豆包整理**」：

   - 自动打开（或切换到）豆包网页版；

   - 自动把整理提示词 + 字幕填入豆包输入框并发送；

   - 豆包输出六个板块：**核心要点**（按主题分小节的 Markdown 笔记）、**术语表**（本视频实际出现的术语 + 一句话解释）、**易错点与疑问**（视频强调的坑 + 待查疑问，疑问不编答案）、**思维导图**（可点击展开的折叠知识树，Obsidian callout 原生渲染）、**关键节点**（`[mm:ss]` 时间点 + 该节点内容）；**原始字幕**由插件在保存时自动附到文末折叠块。

4. 等待豆包整理完成：扩展**自动监控**回答，完成后**自动写入 Obsidian**（若已配置），并在豆包页右上角提示保存路径。

5. **连续处理多个视频**：把链接一行一个贴进队列框 → 点「加入队列」→ 点「开始逐个处理」。之后全程不用再点：第 1 个链接自动填进输入框 → 抓字幕 → **抓完直接把这条发给豆包**（v3.7.95 起，队列模式下不再需要手动点「发送到豆包整理」）→ 豆包整理完自动写入 Obsidian → 收到「笔记已记录」信号后自动填下一个，循环到队列跑完。单条模式（没在跑队列时）仍是"抓取 → 你核对 → 手动点发送"的人工确认。

6. 想结合视频画面补充笔记：直接在豆包对话框里发截图，让豆包结合画面内容扩展。

## 四、常见问题

| 现象 | 原因与解决 |
| --- | --- |
| 豆包页打开但没自动发送 | 插件会自动重试（轮询最多 5 分钟）。仍未发出（豆包页面结构变化时）：插件会把内容**自动复制到剪贴板**并在豆包页右上角弹提示，你在输入框手动粘贴（Ctrl+V）后回车即可。 |
| 第二个视频不生成笔记 | 旧版本存在监控锁死问题，**升级到 v3.7.39+** 并在 `edge://extensions` 点「重新加载」即可。 |
| 公式显示不出来 | 确认笔记是 `$$...$$` / `$...$` 格式；Obsidian 内置 MathJax 原生渲染，打开笔记即显示（阅读/预览模式均可）。不需要额外公式插件。若出现 `U_{C_E}` 这类下标带下划线的问题，升级到 v3.7.46+ 重新生成。 |
| 笔记里有字幕回显/历史对话/重复内容 | 新版已自动过滤：只保留最后一次 AI 回答，按内容指纹去重，字幕回显与杂鱼文案不入库。 |
| 思维导图渲染不出来 | 思维导图已改为可点击展开的知识树（Obsidian 原生 callout 语法 `> [!note]-`），阅读模式点击标题即可展开/收起，无需任何插件。若仍显示为普通引用块，请升级到 v3.7.44+ 并重新生成。 |
| 提示「没有读到字幕」 | 先确认 Edge 已登录 B 站账号（AI 智能字幕需登录）；仍失败则是该视频 / 分 P 确实没有生成字幕，请换有字幕的视频，或多 P 视频加 `&p=N` 试其他集。 |
| 小红书提示「没有可读的字幕」 | 小红书只给部分视频生成 AI 字幕。点开视频看播放器有没有「字幕 / CC」；有字幕还报错，就在那个笔记页上点右下角「笔记」按钮，走页面内抓取（最稳）。 |
| 小红书提示「只返回了空壳页面」 | 该请求没拿到笔记数据。同样改用「在笔记页点悬浮笔记按钮」的方式，从页面内抓取。 |
| YouTube 提示「还没抓到字幕请求」 | 该视频页还没开过字幕。在那个页面的播放器里点开「字幕 / CC」并播放几秒，让插件钩住一次字幕请求，再点「抓取字幕」。 |
| YouTube 提示「该视频没有字幕轨道」 | 该视频本身没有字幕（也没有自动生成字幕）。换有 CC 或自动字幕的视频。 |
| YouTube 抓取失败，提示里带「诊断：…」 | 看诊断内容：`钩子未注入` → 在 `edge://extensions` 重新加载扩展并刷新视频页；`缓存0条且资源记录0条` → 播放器根本没发过字幕请求，在播放器点开 CC 并播放几秒；`有CC按钮` 但兜底仍失败 → 关掉 DevTools（它会占用调试器）后重试。 |
| YouTube 兜底抓取时页面顶部出现黄条 | 这是浏览器对 CDP 调试的提示，抓取结束自动撤销，不用管。 |
| YouTube 抓到的不是中文 | 该视频没有中文轨。插件按"有 `zh` 轨取中文，否则取第一条"选择；需要别的语言时，在播放器里把字幕语言切成目标语言并播放几秒，让钩子缓存该语言，再点抓取。 |
| 字幕内容与视频对不上 | 极少数情况下 B 站接口会返回与分 P 不符的字幕。插件已优先选择与分 P 匹配的字幕，并在发送前弹出字幕开头供你核对；核对不对就不要发送，换链接重试。 |
| 队列卡住不动 | 队列推进靠豆包页发出的「笔记已记录」信号。若卡住，先看状态栏：①显示「处理失败」→ 该条字幕抓取失败或豆包没答上来，点「跳过」继续下一个；②一直显示「处理中」→ 豆包页可能被切到后台或未登录，切回该标签页看一眼；③确认 Obsidian 已配置并能写入（点「测试连接」）。 |
| 队列模式下不想自动发送 | 队列没启动（没点「开始逐个处理」）时，抓字幕不会自动发送，仍是人工确认。已经在跑队列时想暂停，点「清空队列」即可。 |
| 多 P 视频只整理第一集 | 在链接后加 `&p=N` 指定第 N 集。 |
| 想调整笔记格式 | 直接去豆包对话框补充要求（如 "代码单独列表"、"思维导图用蓝色主题"）。 |
| 工具图标点击没反应 | 确认扩展已加载且未禁用；部分浏览器需在扩展详情里允许 "在工具栏显示"。 |
| 新视频的笔记却是上一个视频的内容 | v3.7.98 起已修：发送时记录页面当前回答指纹作为基线，新回答没出现前不落盘；并校验回答里的笔记标题与本次视频一致。若仍遇到，看豆包页是否其实没回复本视频（可能发送没成功），扩展页控制台会打「回答标题与本次视频不一致…暂不保存」，把那行日志发来即可定位。 |
| 豆包生成完了但 Obsidian 里没有笔记 | 先打开扩展页 → 「Obsidian 自动保存设置」→ 点「**测试连接**」：显示"连接正常"就说明 Key 和库都没问题，问题在保存触发（已修：公式修正轮 45 秒内必落盘）；显示"Key 不对"就去 Local REST API 复制 Key；连不上就确认 Obsidian 开着、插件启用、端口 27123。旧版把 API 地址误存成 `extension://...` 时后台会直接报错，v3.7.92 起自动回落 `http://127.0.0.1:27123` 并写回设置。 |
| 等待时间太长 / 反复发"公式修正请求" | v3.7.93 起：①普通模式 12 秒、专家模式 24 秒无新内容就判定写完并落盘（原来专家模式要等 60 秒）；②残留检测会跳过 ```latex 代码块，不再把 `PN 结`、`AI 字幕`、`MCU` 这类大写缩写当成裸公式符号，误判触发率大降；③只有 ≥2 行硬错误才发修正请求，每次笔记最多 1 轮，修正请求最多带 4 行；④修正轮 45 秒没回应就直接保存本地消毒版。 |
| 担心笔记被改错 / 时间戳被编造 | v3.7.96 起：①提示词把保真列为最高优先级，数字、时间、专名、公式、条件限定不许改写，不确定的只写【疑问】；②保存前自动做时间戳自检——笔记里出现而字幕中不存在的 `[mm:ss]` 会在保存提示里标出；③原始字幕自动附在文末折叠块，可逐条对照。若发现某条数据被改错，以文末原文为准手动修正。 |
| 勾了"自动截关键画面"但笔记里没有图 | 截图只在你**已经打开**的那个 B 站视频页里做，插件不会替你新开页面。先打开该视频（地址是 `bilibili.com/video/BV...`），再从该页右下角「笔记」按钮进插件页走抓取流程；插件页状态栏会写具体原因（没有打开该视频页 / 播放区域太小 / 调试器无法附加 / 写入库失败）。截图期间页面顶部出现"正在调试此浏览器"的黄条是正常的，截完自动撤销。若装了其它调试类插件、或该页开着开发者工具，CDP 会附加失败，关掉再试。 |
| 截出来的图是黑的 / 是旧画面 | 视频页在后台标签时，浏览器可能节流画面。插件已开 `Emulation.setFocusEmulationEnabled` 让它照常出画；仍有黑图时，把该视频页切到前台（不用重新抓字幕，重新点一次「抓取字幕」即可重截），或把窗口调大让播放器完整落在视口内（播放器超出窗口的部分截不到）。 |
| 截图有的是空白 / 有的没截全 | v3.8.2 已针对性修：空白多来自"seek 后画面还没解码出来"，现在会等真实呈现帧、校验 `readyState`，并在落盘前做空白检测（近纯黑/纯白且无变化直接丢弃 + 重试一次），状态栏会写明哪个时间点被丢弃及原因；"截不全"多来自黑边占位或播放器比窗口高，现在按 `videoWidth/videoHeight` 内缩到真实画面，并在播放器超高时临时撑高虚拟视口截完撤销。若某时间点反复被丢弃（视频该段确实没缓冲/是纯色板书），把窗口调大或先手动播到该处让它缓冲，再重新点「抓取字幕」。 |
| 每个时间点都报"页面通信失败" | 这是扩展刚「重新加载」后，旧页面里的内容脚本通道失效（页面本身是好的）。v3.8.1 起会自动补注入脚本并重试，成功后状态栏写"已自动补注入页面脚本，无需刷新"；若 5 个时间点全失败还带"补注入脚本失败"，就是该页不允许注入（多为 B 站其它站点域名或页面正忙），F5 刷新该视频页再点一次「抓取字幕」即可。 |
| 时间戳链接点了没反应 | 链接形如 `...?t=192`，用的是 B 站原生跳转参数，分 P 链接会同时保留 `p=`，不会跳到别的集。小红书 / YouTube 的视频不加链接（它们的时间戳参数不同，强行拼会失效）。 |


## 五、隐私说明

- 字幕由本机扩展抓取，写入本机浏览器存储，再填入你自己打开的豆包对话框。

- 发到豆包的内容会进入豆包（这是你主动发送的），请勿发送隐私或敏感内容。

- 项目源码不包含任何个人信息，可直接用于二次开发。
